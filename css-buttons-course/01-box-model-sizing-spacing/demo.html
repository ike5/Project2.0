Module 01 — Box Model, Sizing & Spacing

Size buttons with padding, hit a real 44px target, build a size scale two ways, go full-width, and space rows with gap. Tab through to see :focus-visible.

1 · Size scale — by font-size (§4a)

One .btn rule with em padding. Only font-size changes between sm / md / lg — padding, gap, and radius all scale with it. This is the em payoff.

2 · Size scale — by padding tokens (§4b)

Here the text stays the same size; only the padding tokens (--btn-pad-y/x) change. Use this when you want chunky buttons with normal-sized words — independent control of box vs. type.

3 · Hit-target visualization (§3)

The pink patch is a 44×44px fingertip. The left button clears it comfortably. The right one ignores min-height/width — see the gaps you'd miss on a phone.

✅ ≥ 44px — easy to hit
❌ too small — you'll miss

4 · Full-width mobile CTA (§5)

Inside this "phone," the primary action is display:flex; width:100% — a block-level, full-width thumb target. border-box keeps width:100% honest: padding included, no overflow.

5 · Spaced button row & toolbar (§6)

Spacing lives on the container via gap, never as margins on the buttons. The row wraps cleanly on narrow screens; the toolbar pushes the last action to the right with margin-left:auto.

6 · em-scaling: one slider's worth of control (§2)

The same single .btn rule at four font sizes. Everything — padding, icon gap, corner radius — scales as one unit because it's all in em. Change one number, resize the whole button.

7 · line-height & vertical centering (§7)

Left: tight line-height:1.2 — the label centers exactly. Middle: a bloated line-height:2.4 inflates the box with dead vertical space. Right: a 2-line label stays centered because flexbox — not line-height — does the positioning.

✅ line-height: 1.2
❌ line-height: 2.4
✅ flex-centered, wrap-safe
