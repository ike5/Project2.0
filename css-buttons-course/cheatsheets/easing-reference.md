# Easing Reference — the *feel* of button motion ⏱️

Easing (the `transition-timing-function` / `animation-timing-function`) is what separates a
button that *moves* from a button that feels **alive**. Same distance, same duration —
different curve, completely different personality.

The curve maps **time (x, 0→1)** to **progress (y, 0→1)**. A straight diagonal is `linear`.
Bend it and the motion speeds up, slows down, overshoots, or pulls back.

---

## The 5 built-in keywords

| Keyword | Feel | Use it for |
|---|---|---|
| `linear` | Robotic, constant speed. No accel/decel. | Spinners, marquees, scrolling gradients — anything looping mechanically. |
| `ease` | Gentle start, fast middle, gentle stop (the browser default). | A safe general default when you don't want to think about it. |
| `ease-in` | Starts **slow**, ends fast. Feels like it's *leaving*. | Exits — elements accelerating off-screen. Rarely right for hover. |
| `ease-out` | Starts **fast**, settles slow. Feels responsive and snappy. | **Hover/press feedback and entrances** — the workhorse for UI. |
| `ease-in-out` | Slow → fast → slow. Smooth and symmetric. | Looping/reversing animations (pulse, breathe), longer moves. |

> Rule of thumb: **`ease-out` for things arriving/reacting, `ease-in` for things leaving.**
> Most button hovers want `ease-out` or a custom out-curve — never `ease-in`.

---

## Great named curves (exact `cubic-bezier()` values)

`cubic-bezier(x1, y1, x2, y2)` defines the two control handles; x is locked to 0–1 but **y
can go past it**. Paste these directly.

| Name | `cubic-bezier(...)` | Feel |
|---|---|---|
| easeOutQuart | `cubic-bezier(.25, 1, .5, 1)` | Strong, smooth deceleration. Great default hover-out. |
| easeOutExpo | `cubic-bezier(.16, 1, .3, 1)` | Very snappy arrival, long soft settle. Premium feel. |
| easeOutCirc | `cubic-bezier(0, .55, .45, 1)` | Fast then a rounded, weighty stop. |
| easeInOutCubic | `cubic-bezier(.65, 0, .35, 1)` | Balanced smooth in-and-out. Good for reversible moves. |
| easeOutBack | `cubic-bezier(.34, 1.56, .64, 1)` | **Overshoots** then settles — playful pop. Classic button bounce. |
| easeInOutBack | `cubic-bezier(.68, -.6, .32, 1.6)` | Anticipates *then* overshoots. Big, expressive. |
| gentle overshoot | `cubic-bezier(.34, 1.26, .64, 1)` | A subtle version of easeOutBack — a hint of life, not a bounce. |

---

## Reading the numbers: overshoot & anticipation

The magic is in the **y** values of the control points:

- **`y > 1` → overshoot.** Progress passes 100% then comes back. The element goes *past* its
  target and settles into it — the "pop" of easeOutBack (`y1 = 1.56`). Feels springy/elastic.
- **`y < 0` → anticipation.** Progress dips *below* the start before moving — the element
  winds up backward first, like a jump crouch (easeInOutBack's `y1 = -.6`). Adds weight.
- **`0 ≤ y ≤ 1` → no bounce.** Pure accel/decel, stays within the move.

```
 progress
   1.2 ┤        ╭─╮            ← y>1: overshoots past target, then settles  (easeOutBack)
   1.0 ┤      ╭─╯ ╰──
   0.5 ┤    ╭╯
   0.0 ┤─╮╭╯                  ← y<0: dips back first (anticipation)  (easeInOutBack)
       └────────────── time
```

Overshoot amount scales with how far past 1 you push `y` — `1.2` is a nudge, `1.56` is a
bounce, `2+` is cartoonish. Keep button overshoot tasteful (`1.1`–`1.6`).

## `steps()` — no in-betweens

`steps(n)` jumps in `n` discrete chunks instead of smoothly interpolating. Use it for
sprite-style / ticking motion, or a hard on/off toggle feel.

```css
/* a 4-frame "loading dots" tick — snaps, never glides */
transition-timing-function: steps(4, end);
animation: dots 1s steps(4, jump-none) infinite;
```

`steps(4, end)` holds each frame then jumps; `jump-none` spreads frames evenly across start
and end. Great for retro/mechanical button states.

---

## `linear()` — arbitrary curves (springs without keyframes)

`linear(...)` approximates *any* shape (even bouncy springs) by listing progress stops —
modern browsers can replay a real spring as a single easing function. One-liner idea:

```css
/* a bouncy settle expressed as a linear() easing */
transition-timing-function: linear(0, .25, .7 40%, 1.05 60%, .98 75%, 1);
```

Each value is progress; the optional `%` pins it to a time. It's verbose but lets you paste
spring curves generated by a tool directly into a `transition`.

---

## Ready-to-paste `--ease-*` tokens

Drop this into `:root` and reference the variables everywhere — one place to tune the whole
system's feel.

```css
:root {
  /* decelerations — UI reactions & entrances */
  --ease-out-quart: cubic-bezier(.25, 1, .5, 1);
  --ease-out-expo:  cubic-bezier(.16, 1, .3, 1);
  --ease-out-circ:  cubic-bezier(0, .55, .45, 1);

  /* symmetric — reversible / looping */
  --ease-in-out-cubic: cubic-bezier(.65, 0, .35, 1);

  /* springy — overshoot & anticipation */
  --ease-out-back:      cubic-bezier(.34, 1.56, .64, 1);
  --ease-in-out-back:   cubic-bezier(.68, -.6, .32, 1.6);
  --ease-overshoot-soft: cubic-bezier(.34, 1.26, .64, 1);
}

/* usage */
.btn        { transition: transform .16s var(--ease-out-quart); }
.btn:hover  { transform: translateY(-2px); }
.btn.pop:active { transition: transform .28s var(--ease-out-back); }
```

## Durations that feel right

Motion that's too slow feels sluggish; too fast feels cheap. Pair short durations with
snappy out-curves.

| Interaction | Duration | Notes |
|---|---|---|
| Hover / press feedback | **120–200 ms** | Must feel instant. `ease-out` / `--ease-out-quart`. |
| Entrances (button appears, menu opens) | **250–400 ms** | Room for an overshoot to read. `--ease-out-expo` / `--ease-out-back`. |
| Exits (leaving) | **150–250 ms** | Slightly faster than entrances; `ease-in`. |
| Looping (pulse, shimmer, spin) | **1–2 s** | `linear` for spins, `ease-in-out` for breathing. |

**Guidelines:** the bigger the movement, the longer it can last. A 2px hover lift needs
~140ms; a full card/button springing in can take ~350ms. And always guard motion:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition-duration: .01ms !important; animation: none !important; }
}
```
